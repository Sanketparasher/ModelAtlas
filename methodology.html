Data Architecture & Storage

ModelAtlas is engineered around a zero-backend, client-side data architecture. Unlike conventional SaaS platforms that require server roundtrips, database lookups, and API key billing, ModelAtlas indexes its entire corpus of 384+ models directly inside the user's browser runtime.

Section 02

Benchmark Calibration & Arena Elo Normalization

A foundational problem with public AI leaderboards is historical rating drift. Chatbot Arena's Elo system is an adaptive Bradley-Terry matchmaking scale. Older models from 2023 (such as GPT-4-0314, Qwen 1.5, or Claude-2) accumulated high historical Elos because they only competed against weak contemporaries.

⚠️ The Naive Elo Trap
If raw Elo is sorted without temporal adjustments, GPT-4-0314 (1443 Elo) or Qwen1.5-110B (1431 Elo) would rank above Claude 3.7 Sonnet (1362 Elo) or OpenAI o3-mini (1360 Elo). This misleads users into picking deprecated models.

The ModelAtlas Effective Elo Solution

To preserve scientific ranking integrity without deleting historical records, ModelAtlas applies a verified legacy classification filter:

isObsoleteLegacy(m) := RegexMatch(m.name, m.id, [GPT-4-0314, Claude-1/2, Qwen1.5, Llama-2, Mistral-Medium, Starling-LM...])

getEffectiveElo(m) := m.benchmarks.arenaElo - (isObsoleteLegacy(m) ? 250 : 0)
A -250 Elo baseline normalization penalty restores modern frontier models (Claude 3.7, o3-mini, DeepSeek R1, Gemini 2.5 Pro) to their rightful leadership positions, while keeping historical models accessible for longitudinal analysis.

Section 03

6-Dimension Radar Metric Formulations

The interactive radar chart on the Model Comparison page evaluates every LLM across six normalized axes (0 to 100):

Quality := Math.min(100, Math.round(((getEffectiveElo(m) - 1100) / 270) * 100))
Speed := Math.min(100, Math.round(((m.speedTps || 70) / 140) * 100))
Context := Math.min(100, Math.round((Math.log10(m.contextTokens || 128000) - 4.5) / (Math.log10(2000000) - 4.5) * 100))
Reasoning := Math.min(100, Math.round(m.benchmarks.math || (getEffectiveElo(m) - 1100) / 2.7))
Coding := Math.min(100, Math.round((sweBench * 0.6) + (codingEloScore * 0.4)))
Value := Math.min(100, Math.round((getEffectiveElo(m) * qualityScore) / Math.pow(blendedRate, 0.45) / 3800 * 100))
Context scaling uses a logarithmic transformation so that a 2M token window (Gemini 2.5 Pro) scales proportionally alongside 128k and 200k windows without compressing the lower range.

Blended Token Economics Formula

Real-world API workloads process predominantly input prompt tokens with a smaller ratio of generated output tokens. Simple average pricing misrepresents enterprise cost:

Blended Cost / Million Tokens = (0.75 × Input Price) + (0.25 × Output Price)

Monthly Bill = (Monthly Tokens / 1,000,000) × Blended Cost
For self-hosted open-weights models, ModelAtlas estimates the equivalent amortized GPU compute footprint per million tokens (e.g. ~$0.07/M for 8B up to ~$1.80/M for 671B MoE).

The 3-Tier Multi-Attribute Recommendation Engine

The Model Finder does not use simplistic keyword matching. It implements Multi-Attribute Utility Theory (MAUT) combined with Elimination-by-Aspects (EBA):

Tier 1: Hard Constraint Pruning (Elimination-by-Aspects)
Before mathematical utility scoring begins, candidate models that violate hard physical or regulatory boundaries are immediately pruned:
  • Air-Gapped Sovereign: If the user selects on-premise air-gapped compliance, proprietary cloud models (Claude, GPT-4o, Gemini) receive a strict score of 0.
  • Consumer Local Hardware: If a user has an 8GB or 16GB machine, models with parameter counts >14B receive a score of 0 to prevent out-of-memory kernel panics.
  • Zero Cost Budget: Paid proprietary APIs receive a strict filter if user specifies $0 budget without hosted free tier.

Section 05

Local Hardware Sizing & KV Cache Memory Physics

A frequent failure mode for AI practitioners is downloading an open-weights model that exceeds their physical GPU VRAM. ModelAtlas calculates memory requirements using physical parameter quantization formulas:

VRAM (Model Weights Q4_K_M) ≈ Parameters (B) × 0.55 GB + 1.2 GB (Runtime Overhead)

Examples:
• 7B–8B Model (Qwen 2.5 7B, Llama 3.1 8B) := ~5.5 GB VRAM → Fits 8GB Laptops / M-series Macs
• 14B Model (Qwen 2.5 14B, Phi-4) := ~9.8 GB VRAM → Fits 16GB GPUs (RTX 4060Ti / Mac 16GB)
• 32B Model (Qwen 2.5 32B, QwQ 32B) := ~20.5 GB VRAM → Fits 24GB GPUs (RTX 3090/4090)
• 70B Model (Llama 3.3 70B, Qwen 2.5 72B) := ~40.2 GB VRAM → Requires 2x 24GB GPUs or 64GB Mac Studio
• 671B MoE (DeepSeek R1, DeepSeek V3) := ~400 GB+ VRAM → Requires 8x 80GB Datacenter Cluster

The KV Cache Footprint at Long Context

Running 128k or 256k context locally requires significant additional memory for the Key-Value (KV) Cache:

Memory_KV (Bytes) = 2 × n_layers × n_heads × d_head × n_tokens × bytes_per_element

For a 70B model at 128k tokens in 16-bit precision:
KV Cache alone consumes ~16GB to 32GB of VRAM in addition to model weights.
ModelAtlas explicitly flags the KV cache requirements in AI Advisor responses and hardware guides, recommending FP8 KV cache or vLLM PagedAttention for long-context local deployments.
